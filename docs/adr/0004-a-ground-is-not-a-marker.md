# A ground is not a marker

A branch reaches the cleanup prompt on one of three *Grounds*: *Tracks anchor, ahead*, *Untracked, tip in anchor*, or *Gone*. The prompt says which because a branch name alone does not explain why it was offered. These names state the ref evidence instead of claiming that the branch's work landed. The obvious rendering is a glyph alongside the `●` and `↑N` already in the column. We render it as words instead. Per [ADR 0001](./0001-warned-means-forceable.md), a shown *Marker* licenses forcing. A ground destroys nothing, so admitting one into the glyph vocabulary would grant force permission on the strength of a fact that warns of no loss.

## Consequences

- **The grounds are typed at the git boundary, not re-derived.** `stale_branches` carries the ground out with each branch rather than returning bare names, so the one place that decides what makes a branch stale stays the one place that knows why. The alternative — recomputing it in the app layer from refs it already holds — is a second judgement free to drift from the first, which is the drift `marker.rs` exists to prevent.
- **The words are the glossary's words.** Rows read `tracks anchor, ahead`, `untracked, tip in anchor`, or `gone`, not `landed` or `merged`. The first two are proxies and can describe a branch with no work of its own. Naming only what Git established keeps the prompt honest. `gone` is also what `git branch -vv` prints.
- **The ground changes what is shown, not what is ticked.** *Gone* is firmer evidence because a deleted upstream is a fact, while the anchor grounds can misfire on a branch cut from an anchor that later moved or was already ahead. That supports pre-ticking riskless *Gone* rows, but we deliberately do not. A destructive default should change on evidence of use, not on the day the ground first becomes visible.
